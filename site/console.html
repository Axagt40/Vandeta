Live console

Talk to the board

This is the firmware's own text console, not a shell: every line goes straight to the board over USB and its answer is printed here. Turn on Config → System Config → Developer Options on the device first, or the developer verbs will be refused.

Not connected. opening the port resets the board

        What this is. The same console a serial monitor shows:
        one command per line, answers printed as the firmware writes them. No
        files are uploaded and nothing is stored on the board.
      

      

        Developer Options must be on. Without it, the board
        answers plain-text commands only, and ui,
        move, file, livepatch and the rest
        are refused by the gate.
      


      

        
Try this


ui                  screen you are on, and its rows
ui move down        move the highlight, read the new screen
ui select           open the highlighted row
mem                 heap, internal DRAM, PSRAM
errors              the error ring (ESP-IDF, Arduino, printf)
info                firmware version and board
help                every verb this build knows

        

          Full reference: console documentation.
        

      


      

        Nothing appears after connecting
        

          The board resets when the port opens, so give it a second and watch
          for its boot lines. If the log stays empty, another program is holding
          the port — close serial monitors, the bruceapp
          mirror, or an esptool session.
        

      


      

        Commands are refused
        

          That is the Developer Mode gate, not a browser problem. Turn on
          Config → System Config → Developer Options
          and try again; usbdebug status reports the current state.
