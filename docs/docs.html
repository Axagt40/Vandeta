Installation

The release image is pre-merged — bootloader, partition table and application in one file — so it is a single write at offset 0x0.

Filevandeta.bin and vandeta.bin.sha256
Size4,648,576 bytes
sha2562a2582e4f80fb2f86543fe108622bb357bf831f777899f01c09e842711552a76
Offset0x0 — never another offset
ChipESP32-S3, 16 MB flash
Two channels. The official release is vandeta 1.2 — 2a2582e4…52a76, 4,648,576 bytes — and is what the table above describes. The pre-release is vandeta 1.3 — d32f9ea6…26e62, 4,781,792 bytes: identical procedure at 0x0, but it is published early for testing and may still change. The flasher offers both; docs/firmware/vandeta-pre.bin is the bundled copy of the pre-release image.

1. Verify the download

sha256sum -c vandeta.bin.sha256

2. Flash it

esptool.py --chip esp32s3 --port /dev/ttyACM0 --baud 115200 \
    write_flash 0x0 vandeta.bin

Keep 115200. The board's USB-Serial-JTAG link, not the host, sets the real speed; a write at 921600 stopped part-way during testing and left the app partition incomplete. If a flash stops, the board will not boot until it is flashed again — retry at 115200.

On Windows the port is something like COM5. The board exposes USB-Serial-JTAG while it is in console mode, which is the port esptool talks to. Prefer a browser? The flasher on this site does the same write, after checking the image hash.

Port modes

USB IDWhat it isWhat to do
303a:1001 USB-Serial-JTAG console Correct for flashing and for the console.
303a:0002 USB Mass Storage mode Leave that mode on the device; no host command can switch it.

Clean install

Erase first when you want to drop saved settings and the configuration partition: 

esptool.py --chip esp32s3 --port /dev/ttyACM0 erase_flash
esptool.py --chip esp32s3 --port /dev/ttyACM0 --baud 115200 \
    write_flash 0x0 vandeta.bin

Flashing this image does not touch the SD card. If the flash cannot start, hold BOOT while plugging the cable in and retry.

Linux: if lsusb shows 303a:1001 but no /dev/ttyACM0 appears, the driver is not loaded: sudo modprobe cdc_acm.
Wrong offset, wrong boot. A merged image written at any offset other than 0x0 will not start. Re-flash at 0x0 after an erase_flash to recover.

SD card layout

The firmware runs without a card, but scripts, the universal IR libraries, portals and wardriver captures live on it.

PathWhat goes thereOptional
/scripts, /BruceScripts, /BruceJS JavaScript files (.js / .bjs) picked up by the interpreter, listed as Apps. Yes, but nothing to run without it
/infrared/Universal/ The Flipper IR libraries (TV, AC, fans, audio, projectors, LEDs) behind Universal Remote. The same files ship in sd_files/infrared/Universal/ in the repository. Yes — Universal Remote lists only the categories it finds
/bruce/subghz/wardriver Wardriver recordings, one .sub file per burst, plus _dec.sub files written by Identify & save. Created by the wardriver
/portals/en/ Captive-portal pages; /portals/en/rickroll.html is the one the rickroller script looks for, falling back to its built-in copy. Yes

Card files can be inspected on the device (Files, or ls / cat / storage read on the console) or written over USB with file write <path> <text>.

USB console

Turn on Config → System Config → Developer Options → Developer Mode, then talk to the board over the same USB cable at 115200 baud. One switch arms the console and the speed profile together.

The console boots in plain text and only switches modes when asked, so a mis-typed command cannot leave the board unusable. Every command answers immediately — none waits on a modal banner. The live console on this site is the same connection in a browser tab.

Features

Bruce's menus, apps, radios and script ecosystem are unchanged and still present. These are the layers Vandeta adds on top.

USB console — Developer Options
  • A single Developer Mode switch arms the console and the speed profile.
  • ui, move and press drive the menus and print the screen you land on, including pages that build a local option list.
  • The error ring collects ESP-IDF, Arduino and plain printf() lines; turning Developer Mode off releases the console's queues and RX buffer.
Sub-GHz / CC1101
  • Serialized SPI access to the radio the display shares, so scans, reads, spectrum, the analyzer and the wardriver run reliably.
  • Flipper-style Frequency Analyzer: coarse hop over the three CC1101 bands, 20 kHz fine pass, held readout, last three hits and a sortable log page.
  • SubGHz Wardriver records whole bursts straight to the card, rejects short-pulse noise, replays verbatim and can decode a capture to _dec.sub.
nRF24 (2.4 GHz)
  • Raw capture in the pseudo-promiscuous configuration: CRC off, auto-ack off, shortest address width, degenerate addresses on all six pipes.
  • 3 s capture or a hop over 0–125, RGB-remote presets (MiLight RGBW / CCT / RGB+CCT / RGB, FUT020), channel scan, multi-frequency detect, save/load, replay and packet analysis.
  • Capture buffers come from PSRAM, keeping about 36 KB of internal DRAM free for WiFi and BLE.
Packet Monitor
  • One dashboard fed by WiFi, BLE, nRF24 and sub-GHz, opened from each menu with its radio preselected.
  • Filters, per-radio and per-type counters, packets per second, busiest channel, CSV export and PCAP export of captured WiFi frames.
BLE
  • BLE Detector: live, RSSI-sorted table with Apple Continuity types decoded, distance estimate, paging, hold and clear. Receive-only.
  • Capture & replay with a live counter, a JavaScript GATT client, and headless advertisement spam.
  • Bring-up and teardown keep internal DRAM available, and WiFi features free BLE memory first.
Infrared
  • Universal Remote over the Flipper libraries — 2,858 codes across TV, AC, fans, audio, projectors and LEDs — with pause and cancel during a sweep.
  • Brand AC remotes for twelve makes send a full state frame: power, mode, 16–30 °C, fan.
  • Hand-written RCA and NEC42 encoders, and TV-B-Gone shares the same pause policy.
WiFi
  • One flat Wifi Atks page and one Target Atks page, with no nested duplicate menus.
  • ARP spoofing, DNS spoofing and HTTP interception that reach WPA2/WPA3 clients over the encrypted station link.
  • MITM Attack on the Wifi Atks page: pick the network from a scan, the target mode (all devices or one host), and one payload from /BruceSpoof/. It pairs each target with its gateway, shows a live activity feed of what the payload is doing, and restores every ARP mapping when you leave the page.
  • The payload is the JS MITM API in plain text: page (200 + HTML), redirect (302), dns (answer lookups), target, and fallback — e.g. answer DNS instead when no HTTP request landed. dns answers accept gateway / this and are resolved per query, so a payload loads before the board has joined a network.
  • A ready-to-use /BruceSpoof/test.mitm (page html/test.html) proves the whole path on a victim without any external site. The board completes the client's TCP handshake itself, so no Web UI or other port-80 listener has to run.
  • Also drivable headlessly with mitm (plus dnsinject / htmlint for one engine at a time).
  • Evil-twin portal refuses with a readable error when DMA memory is short, and attacks can run headlessly with a deadline.
BadUSB / HID
  • HID Settings page: footprint (VID, PID, manufacturer, product, serial), layouts with import/export, HID device type, timing and a payload manager.
  • Payloads keep typing past characters the active layout cannot express.
  • Apple/BLE patch and BadBLE name, so the BLE keyboard is listed by iOS and macOS and pairs Just Works.
JavaScript API
  • arpSpoof, dnsSpoof and httpInterceptor, plus the wifi injection and capture bindings.
  • BLE GATT client, nRF24 capture and replay, IR, sub-GHz and storage bindings.
  • scriptFolder runs background jobs, with setShared/getShared for state.
Menus and navigation
  • Breadcrumb path, n/total counter and scrollbar on long lists, plus an encoder hint bar.
  • A child menu works on its own copy of the option list, so it cannot disturb the page it was opened from.
  • Capture screens show progress and Press BACK to stop; only Back aborts.
Board support and memory
  • The CC1101 and the display share one SPI bus, guarded by a TFT_eSPI bus lock for whole radio operations.
  • The WiFi tap brings the radio up directly and releases the driver when it closes; starting a WiFi feature frees BLE, the Web UI and stale captures first.
  • BLE bring-up is checked against the full ~56 KB it needs, instead of the largest contiguous block alone.

Build from source

PlatformIO Core 6.1.19 or newer and python3. The first build needs network access to resolve lib_deps; they are cached under .pio/ afterwards. 

pio run -e lilygo-t-embed-cc1101

This produces vandeta-lilygo-t-embed-cc1101.bin and a merged copy named vandeta.bin in the project root (build.py runs esptool merge-bin as a post-action). The default environment is lilygo-t-embed-cc1101.

BRUCE_VERSION is a build_flags define, so changing it invalidates the build cache — expect a 15–25 minute rebuild.

Troubleshooting

Start with the cable and the offset; those account for most failures.

SymptomCauseFix
Device boots to a blank screen The merged image was written at the wrong offset. erase_flash, then write at 0x0.
No /dev/ttyACM0 (or no port at all) Mass Storage mode (303a:0002), a power-only cable, or the host driver is not loaded. Leave Mass Storage mode on the device, change the cable, and on Linux run sudo modprobe cdc_acm.
esptool cannot connect The board is not in download mode. Hold BOOT while plugging the cable in, and confirm the port with lsusb | grep 303a.
Scripts list is empty No scripts on the card, or the wrong folder. Put .js files under /scripts, /BruceScripts or /BruceJS; verify with the SD Card Manager.
Console commands are refused Developer Mode is off. Turn on Config → System Config → Developer Options → Developer Mode, then check usbdebug status.
Injection “works” but nothing reaches the victim Application-layer injection only lands on OPEN/WEP networks. Use the target pages against a network you are authorised to test, or use the encrypted-link engines (ARP/DNS/HTTP) as designed.
A radio tool says it has no memory Only one radio stack fits at a time on this board. Leave the other radio's screen first; WiFi bring-up frees BLE and stale captures automatically.

Hosting this site

Three free options, and the one constraint that decides between them: browsers only expose Web Serial — which the flasher needs — on a secure origin. That means https:// or http://localhost. A plain http://192.168.x.x page loads fine but its Connect button will not work.

WhereHowFlasher works?
GitHub Pages Free for public repositories: Settings → Pages → Deploy from a branch → main → /docs. The site is then served over HTTPS at axagt40.github.io/Vandeta/. Yes
This computer python3 -m http.server 8000 --directory docs, then open http://localhost:8000. No account, no upload, works on a train. Yes — localhost is a secure origin
Phone (Termux / proot) python3 -m http.server 8000 --directory docs in Termux or Debian; other devices open http://<phone-ip>:8000. For HTTPS, run a free tunnel (for example a cloudflared quick tunnel) in front of it. Only through the tunnel — plain LAN HTTP is not secure
The board plugs into the computer, not the phone. The page may be served from anywhere, but navigator.serial only sees devices attached to the machine running Chrome. Serving this folder from a phone is fine for reading the docs; flashing wants the board on the same computer as the browser.
Internet, but no account. The flasher reads the release list from the GitHub API, pulls the image from the repository and imports the pinned esptool-js 0.7.0 bundle from unpkg. Its two channel buttons follow GitHub's own flags: Official is the newest release that is not marked pre-release, Pre-release the newest one that is, and that button stays greyed out while no pre-release exists. With no connection it falls back to the copies in docs/firmware/, labelled as an offline copy.

The flasher always installs the newest release of the channel that is selected, so cutting a release needs no site edit. Keep docs/firmware/vandeta.bin (official) and docs/firmware/vandeta-pre.bin (pre-release) with their .sha256 files current anyway: that is what an offline visitor gets, and the page still refuses any image whose hash does not match the release digest.
