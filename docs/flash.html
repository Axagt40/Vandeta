Browser flasher

Flash it from this page

Chrome or Edge on desktop, a USB-C cable, and the board. The image is downloaded here, checked against its published SHA-256, written at 0x0 and the board is reset. Nothing is installed on your computer.

flasher log

      
        

        0x0, or it will not boot. The image is merged
        (bootloader + partition table + app). This page always writes at
        0x0.
      


      

        If a flash stops part-way (The chip stopped
        responding), the app partition is left incomplete and the board
        will not boot until it is flashed again. Retry at 115200:
        this board's USB-Serial-JTAG link is what limits the speed, and a write
        at 921600 failed on it during testing.
      


      

        Requirements. Desktop Chrome or Edge 89+, a data-capable
        USB-C cable, and nothing else holding the port (close any serial monitor
        or esptool session). Opening the port resets the board once — that
        is normal.
      


      

        The board does not show up
        

          Check the cable first. 303a:1001 is console/JTAG mode and
          is what flashing needs; 303a:0002 is USB Mass Storage mode
          and must be left on the device. On Linux, if lsusb shows
          the board but no port appears, load the driver:
          sudo modprobe cdc_acm.
        

      


      

        Prefer the command line?
        

          sha256sum -c vandeta.bin.sha256 then
          esptool.py --chip esp32s3 --port /dev/ttyACM0 --baud 921600 write_flash 0x0 vandeta.bin.
          The docs page has the full procedure.
        

      


      

        Flashing uses esptool-js
        0.7.0 from unpkg, pinned. Everything else on this page is served from
        this site.
