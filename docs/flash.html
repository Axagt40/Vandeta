Install the latest Vandeta

Plug the board in, press one button. The page reads the newest release from GitHub, downloads it, checks its SHA-256 against the published checksum, writes it at 0x0 and resets the board. Nothing is installed on your computer.

        0x0, or it will not boot. The image is merged
        (bootloader + partition table + app). This page always writes at
        0x0.
      


      

        Requirements. Desktop Chrome or Edge 89+, a data-capable
        USB-C cable, and nothing else holding the port (close serial monitors or
        esptool sessions). Opening the port resets the board once — that is
        normal.
      


      

        If a flash stops part-way (The chip stopped
        responding), the app partition is incomplete and the board will
        not boot until it is written again. Retry at 115200 in
        Advanced: the write at 921600 failed on this board during testing.
      


      

        The board does not show up
        

          Check the cable first. 303a:1001 is console/JTAG mode and
          is what flashing needs; 303a:0002 is USB Mass Storage mode
          and must be left on the device. On Linux, if lsusb shows
          the board but no port appears: sudo modprobe cdc_acm.
        

      


      

        Where the image comes from
        

          GitHub's release assets cannot be fetched from a page on another
          origin, so the image is read from the repository: the release tag
          first, then main, then the copy bundled in this site. A
          tag snapshots the repository as it was when it was cut, so any copy
          that does not match the digest GitHub reports for the release asset is
          skipped and the next source is tried.
        

      


      

        Flashing uses esptool-js
        0.7.0 from unpkg, pinned.
